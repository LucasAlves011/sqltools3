SQL*Plus Script Commands

SQLTools recognises a subset of SQL*Plus script commands. These commands control script flow, manage substitution variables, declare bind variables, and handle database connections. They are processed line-by-line when a script is executed with F5 (Run Script).

Command keywords are case-insensitive. Most keywords may be abbreviated to their shortest unambiguous prefix (e.g. VAR for VARIABLE, EXEC for EXECUTE, CONN for CONNECT).

Quick reference

Command Purpose
REM / REMARK Comment — the rest of the line is ignored.
PROMPT Display a message in the Output window.
DEFINE Create or display a text substitution variable.
UNDEFINE Remove a substitution variable.
EXECUTE / EXEC Execute a single PL/SQL statement.
DESCRIBE / DESC Describe a database object. (not implemented, use "Find Object" F12)
CONNECT Connect to a database.
DISCONNECT Disconnect from the current database session.
VARIABLE / VAR Declare a bind variable.
PRINT Display the current value of a bind variable.

REM / REMARK

REM [text]
REMARK [text]

Marks the rest of the line as a comment. The entire line is ignored during execution and produces no output. Use REM or the full keyword REMARK interchangeably.

Example

REM Retrieve all active employees
SELECT * FROM employees WHERE active = 1;

REMARK End of report script

Note: SQL and PL/SQL comments (-- single line and /* block */) are also supported inside SQL statements and are distinct from the REM command, which applies only to a script command line.

PROMPT

PROMPT [text]

Writes text to the Output window. Everything on the line after the PROMPT keyword is displayed verbatim, including leading spaces. If no text is given an empty line is written.

Example

PROMPT Starting data load...
PROMPT
PROMPT Done.

DEFINE

DEFINE variable = value
DEFINE variable
DEFINE

DEFINE creates a substitution variable whose value is substituted for every occurrence of &variable or &&variable found in subsequent SQL or script lines.

Form Behaviour
DEFINE var = value Assigns value to var. The value may be an unquoted word or a quoted string ('text' or "text").
DEFINE var Displays the current value of var, or reports it as undefined.
DEFINE Lists all defined substitution variables. (not implemented)

Substitution in SQL

Place &variable anywhere in a SQL or PL/SQL statement. Before execution SQLTools replaces each occurrence with the stored value. If the variable has not been defined, a prompt dialog asks you to supply a value for that execution.

Notation Behaviour
&variable Substituted each time it is encountered. If undefined, prompts for a value which is used only for that single occurrence.
&&variable Substituted and the entered value is saved as a DEFINE for the remainder of the session.
&variable. (trailing dot) The dot terminates the variable name when the name is immediately followed by alphanumeric text, e.g. &tbl.s expands to emps when tbl is defined as emp.

Example

DEFINE dept = 10

SELECT ename, sal
  FROM emp
 WHERE deptno = &dept;

UNDEFINE

UNDEFINE variable

Removes the substitution variable variable. After this command, any reference to &variable in subsequent statements will prompt for input. Has no effect if the variable was not defined.

Example

DEFINE schema = HR
SELECT * FROM &schema..employees;
UNDEFINE schema

EXECUTE / EXEC

EXECUTE pl/sql_statement[;]
EXEC pl/sql_statement[;]

Executes a single PL/SQL statement. SQLTools automatically wraps the statement in an anonymous block: 

BEGIN
        pl/sql_statement;
END;

The trailing semicolon after the statement is optional. Bind variables declared with VARIABLE can be referenced using the :name notation.

Example

VARIABLE result NUMBER

EXECUTE :result := 2 + 2;

PRINT result

DESCRIBE / DESC

DESCRIBE object_name
DESC object_name

This command is recognised but implemented. Place the cursor over an object name and use "Find Object" F12.

CONNECT

CONNECT [username/password@database]
CONN [username/password@database]
Form Behaviour
CONNECT Opens the Connect dialog box.
CONNECT user/pwd@db Connects immediately using the supplied credentials without showing the dialog.
CONNECT user/pwd@host:port:sid Same as above but bypass tnsnames.ora and make connection string using provided host, port and sid.
CONNECT user/pwd@host:port/service Same as above but bypass tnsnames.ora and make connection string using provided host, port and service.

Example

CONNECT hr/hr@orcl
CONNECT scott/tiger@192.168.56.107:1521/pdb2

DISCONNECT

DISCONNECT

Disconnects from the current Oracle session. Any uncommitted transactions are rolled back. Subsequent SQL execution will fail until a new CONNECT is issued.

VARIABLE / VAR

VARIABLE name datatype[(size)]
VAR name datatype[(size)]

Declares a bind variable that persists for the duration of the session. Once declared, the variable is visible in the Bind Variables panel and can be referenced in any SQL or PL/SQL statement using the :name notation.

Supported data types

Data type Description
VARCHAR2(n) Variable-length character string. n is the maximum number of characters (1 – 4000). Size is required.
CHAR(n) Fixed-length character string, always padded to n characters with spaces, emulating Oracle’s CHAR datatype. n is required (1 – 2000).
NUMBER Oracle’s native arbitrary-precision number. Bound using the SQLT_VNU OCI type, so overloaded PL/SQL procedures can disambiguate NUMBER from string types.
BINARY_FLOAT IEEE 754 single-precision (32-bit) floating-point. Maps to Oracle’s BINARY_FLOAT column type. Supports special values NaN, Inf, -Inf.
BINARY_DOUBLE IEEE 754 double-precision (64-bit) floating-point. Maps to Oracle’s BINARY_DOUBLE column type. Supports special values NaN, Inf, -Inf.
DATE Oracle date and time (year, month, day, hour, minute, second). Displayed and entered using the NLS date format configured in the Grid settings.
CLOB Character Large Object. Can store large text values. The display length in the Bind Variables panel is limited by the Grid Max LOB Length setting.
REFCURSOR Reference cursor. Typically used as an OUT parameter in a PL/SQL procedure call. The cursor contents are not displayed in the Bind Variables panel after execution.

Note: Redeclaring a variable that already exists replaces it and resets its value to NULL.

Examples

VARIABLE emp_name  VARCHAR2(100)
VARIABLE dept_id   NUMBER
VARIABLE hire_date DATE
VARIABLE results   REFCURSOR

-- Assign values and call a procedure
EXEC :emp_name := 'KING';
EXEC :dept_id  := 10;

-- Use bind variables in a query
SELECT * FROM emp
 WHERE ename = :emp_name
   AND deptno = :dept_id;

-- Open a ref cursor from a stored procedure
EXEC my_pkg.get_emp(:dept_id, :results);

PRINT

PRINT variable_name

Writes the current value of the named bind variable to the Output window. The variable must have been previously declared with VARIABLE. Particularly useful for inspecting OUT parameters after calling a stored procedure with EXECUTE.

Note: PRINT without an argument (to print all bind variables) is not implemented.

Example

VARIABLE v_count NUMBER

EXEC SELECT COUNT(*) INTO :v_count FROM employees;

PRINT v_count

Scripting example

The following complete script demonstrates several commands working together: 

REM -------------------------------------------------------
REM  Department headcount report
REM -------------------------------------------------------

DEFINE dept_no = 20

VARIABLE v_name   VARCHAR2(50)
VARIABLE v_count  NUMBER

PROMPT Fetching data for department &dept_no...

EXEC SELECT dname INTO :v_name FROM dept WHERE deptno = &dept_no;
EXEC SELECT COUNT(*) INTO :v_count FROM emp  WHERE deptno = &dept_no;

PRINT v_name
PRINT v_count

SELECT ename, job, sal
  FROM emp
 WHERE deptno = :v_count;

UNDEFINE dept_no
